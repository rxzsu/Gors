# GoRs v0.1

Экспериментальная версия языка и CLI: **0.1.0**. Компилятор написан на Go,
проверки типов и владения общие для C23- и Go-бэкендов.

## Запуск

Нужен Go 1.22+; для C-бэкенда также GCC 14+ (или совместимый Clang с C23).

```sh
go build -o gors ./cmd/gors
./gors --version
./gors run examples/modules/main.gors --backend c
./gors run examples/modules/main.gors --backend go
./gors build examples/modules/main.gors -o app --backend c
./gors emit examples/modules/main.gors --backend go
```

`run`, `build`, `emit` принимают путь к одному входному файлу и загружают его
импорты. `build` создаёт бинарник по `-o`; `run` использует временный каталог.
Бэкенд по умолчанию — C, если найден C-компилятор, иначе Go. Некорректное имя
бэкенда является ошибкой. `--opt=-O3` задаёт флаг оптимизации C-компилятора.

## Файлы и видимость

```go
// math.gors
pub struct Point { x: int, y: int }
fn square(x: int) -> int { return x * x }
pub fn (p: &Point) norm2() -> int { return square(p.x) + square(p.y) }

// main.gors
import math "math.gors"
fn main() {
    let p = math::Point { x: 3, y: 4 }
    println(p.norm2())
}
```

Один файл — один модуль. `import alias "relative/path.gors"` разрешается
относительно файла с импортом, а не текущего рабочего каталога. Абсолютные
пути и циклы импортов запрещены. Один физический файл загружается один раз;
разные файлы имеют отдельные пространства глобальных имён. Импорты не
реэкспортируются: каждый файл объявляет свои зависимости явно.

Функции, структуры и методы приватны по умолчанию; `pub` открывает их другим
модулям. К импортируемым функциям и типам обращаются через `alias::name`.
Все поля экспортируемой структуры доступны; отдельной видимости полей пока нет.
Импортируемые методы вызываются обычным `value.method()`.

`main` входного файла не принимает параметров и ничего не возвращает.
Глобальных переменных и кода на уровне модуля нет. Загрузка модулей не выполняет
код. Ошибки в импортированном файле показываются вместе с его исходным текстом.

## Типы и выражения

Типы: `int` (64 бита), `float` (64 бита), `bool`, `string`, структуры, `[]T`,
`Option<T>`, `Result<T, E>`, локальные ссылки `&T` и `&mut T`.

Есть арифметика, сравнения, `&&`, `||`, `!`, поля, вызовы, индексация и строковая
конкатенация `+`. `&&` и `||` вычисляют правую часть только при необходимости.
Вызовы в аргументах вычисляются слева направо, в том числе рядом с `?`.
Рекурсивные типы, пользовательские generics и неявные преобразования отсутствуют.
Переполнение целых и точный формат вывода чисел с плавающей точкой пока не имеют
единого переносимого контракта между бэкендами.

```go
fn sum(xs: []int) -> int {
    let mut total = 0
    let mut i = 0
    while i < len(xs) {
        total = total + xs[i]
        i = i + 1
    }
    return total
}
```

Встроенные операции: `println(...)`, `print(...)`, `len(value)`,
`push(&mut slice, value)`, срезы `s[low:high]` для слайсов и строк. Индексация слайса проверяет границы; ошибка завершает
процесс с кодом 1 и сообщением `gors: index N out of bounds (len M)` в stderr.
Нормальное завершение программы имеет код 0. Аварийное завершение не разворачивает
области видимости; проверка утечек предназначена для успешных запусков.

Срез `s[low:high]` создаёт независимую копию диапазона; исходное значение
остаётся доступным. Пропущенные границы равны 0 и `len(s)`. Для слайсов
поддерживаются только копируемые элементы (`int`, `float`, `bool`): строки,
структуры, вложенные слайсы и варианты требуют глубокого копирования и пока
отвергаются с `E183`. Строки можно разрезать по байтовым индексам.
Оба бэкенда проверяют `0 <= low <= high <= len(s)` и при нарушении завершаются
с кодом 1 и сообщением `gors: slice bounds out of range [L:H] (len N)`.

## Управление потоком и варианты

Операторы: `let`, `let mut`, присваивание, `if`/`else`, `while`, `for`, `break`, `continue`, `return`,
`if let`, `match`, вложенные блоки. Функция с результатом должна возвращать
значение на всех путях. Операторы после безусловного возврата, break или continue отвергаются.
`let _ = expression` вычисляет и отбрасывает значение; `_` нельзя читать.

```go
fn greeting(ok: bool) -> Option<string> {
    if ok { return Some("hello") }
    return None
}
fn main() {
    match greeting(true) {
        Some(message) => { println(message) },
        None => { println("empty") },
    }
}
```

`match` поддерживается как оператор (`MatchStmt`), так и как выражение (`MatchExpr`).
Он вычисляет вход ровно один раз и потребляет
его. Для `Option` обязательны `Some(binding)` и `None`; для `Result` —
`Ok(binding)` и `Err(binding)`. Порядок веток произвольный. Дубликаты, чужие
варианты и неполное покрытие являются ошибками. Ветвь может быть выражением (`Some(v) => expr,`) или блоком (`Some(v) => { ... }`).
В `MatchExpr` ветви вычисляются в единый результирующий тип.
`Some(_)`, `Ok(_)`, `Err(_)` отбрасывают содержимое.
Вложенные шаблоны, guards и универсальная ветка `_ =>` пока не поддерживаются.

`None` требует контекста типа. `Ok` и `Err` требуют контекста `Result<T,E>`
(аннотация локальной переменной или тип возвращаемого значения).
`value?` разворачивает `Ok`, а при `Err` немедленно возвращает ошибку из текущей
функции. Тип ошибки должен совпадать; тип успешного результата может отличаться.

## Владение и ссылки

`int`, `float`, `bool` копируются. Строки, слайсы, структуры и варианты
перемещаются при передаче по значению, связывании и возврате. После перемещения
исходное место нельзя читать. После перемещения поля или элемента слайса
проверка консервативно считает перемещённым исходное значение целиком.

Переменные неизменяемы без `mut`. У значения может быть много общих займов или
один исключительный. Общую ссылку можно скопировать в другую локальную ссылку:
заём сохраняется до последнего использования любого её псевдонима.
Копировать `&mut` нельзя; передача `&mut` параметру — временное перезаимствование.
Конфликтующие ссылки в аргументах одного вызова запрещены.

Ссылки могут быть локальными переменными, параметрами или возвращаться из
функций и методов по правилам Lifetime Elision (сокращения времён жизни):
- Функция, возвращающая ссылку (`&T` или `&mut T`), должна иметь ровно один
  входной ссылочный параметр. Для метода со ссылочным получателем время жизни
  связывается с ним; для метода с получателем по значению нужен ровно один
  ссылочный параметр среди остальных аргументов.
- Возвращаемая ссылка обязана происходить из этого параметра; возврат ссылок на локальные
  переменные запрещён.
- В точке вызова заём аргумента автоматически продлевается на время жизни возвращённой ссылки.
- Поддерживается разыменование через унарный оператор `*` (`*r` и `*r = value`).
Ссылки по-прежнему нельзя хранить в полях структур, слайсах или `Option`/`Result`.
Перенос владеющего поля через ссылку запрещён.

Для простоты анализа затенение локальных имён запрещено. В цикле нельзя
перемещать владеющее значение, объявленное вне этого цикла: его нужно создавать
внутри каждой итерации или передавать по ссылке. Займы, используемые повторно,
сохраняются через обратное ребро цикла. Состояние владения объединяется по
веткам `if`, `if let`, `match`; анализ может отвергать безопасную программу.

C-бэкенд освобождает владеющие значения при нормальном выходе из области,
возврате и распространении ошибки через `?`. Временные значения освобождаются
после выражения. При замене старое значение освобождается после вычисления нового.
При частичном перемещении освобождаются оставшиеся поля. Для диагностики памяти:

```sh
GORS_LEAKCHECK=1 ./app
```

## Проверки и сборки

```sh
go test -count=1 ./...
go vet ./...
go run ./tools/package -out dist
```

Тесты компилируют и запускают программы через оба бэкенда, проверяют вывод,
завершение, диагностику, отрицательные примеры владения и C-счётчик утечек.
Для выполнения всей матрицы нужны Go и GCC с C23.

Упаковщик создаёт Linux amd64 `.tar.gz`, Windows amd64 `.zip` и `SHA256SUMS`.
Архивы включают CLI, README, эту спецификацию и changelog. Создание архивов
не публикует релиз. Workflow CI описывает проверки Linux/Windows и сборку
артефактов; запуск на GitHub требует отдельного push в репозиторий.
